The 429 problem

A Claude API call fails with HTTP 429 Too Many Requests the moment any one of three independent ceilings is exceeded in a rolling minute: RPM (requests/min), ITPM (input tokens/min) and OTPM (output tokens/min). Most teams size for RPM, ship, and then 429 on ITPM under real traffic — because Anthropic publishes ITPM and OTPM per model, and the numbers differ by more than 10× between Opus and Sonnet at the same tier. A single per-tier figure is structurally wrong; you have to read the cell for your model.

The cache-aware ITPM rule — the biggest non-obvious lever

cache_read_input_tokens do NOT count toward ITPM (for every current model — the sole exception is the legacy Claude Haiku 3.5). input_tokens and cache_creation_input_tokens still count. OTPM ignores max_tokens and only counts tokens actually generated.

This is the lever almost nobody sizes for. If your workload has a large stable prefix — a long system prompt, a fixed tool schema, retrieved documents reused across turns — prompt caching can remove the bulk of your billed input tokens from the ITPM count entirely. A workload that 429s on ITPM uncached can sit comfortably under the same limit once the prefix is cached, with no tier upgrade. Treat caching as a throughput multiplier, not just a cost discount.

Per-second quantization: the burst trap

"Per minute" is a convenience label. Limits are enforced with a token bucket that refills roughly per second: 60 RPM ≈ 1 request/second. If your tier allows 2,000 RPM that is only ceil(2000/60) ≈ 34 requests in any single second. A tight loop that fires 100 requests in one second 429s immediately even though the 60-second total is well under 2,000. Smooth traffic with a client-side limiter sized to the per-second figure, not the per-minute headline.

Model-pool sharing

Rate limits are pooled by family, not by exact version. The Opus ceiling is shared across Opus 4.7 / 4.6 / 4.5 / 4.1 / 4; the Sonnet ceiling across Sonnet 4.6 / 4.5 / 4. Routing some traffic to an older Opus version to "spread load" buys you nothing — it draws from the same bucket.

FAQ

What is the difference between ITPM and OTPM?
ITPM is input (prompt) tokens per minute; OTPM is output (generated) tokens per minute. They are independent ceilings — you can be fine on one and 429 on the other.
Do cached tokens count toward Claude's ITPM limit?
No — cache_read_input_tokens are excluded from ITPM for all current models (only legacy Haiku 3.5 still counts them). input_tokens and cache_creation_input_tokens do count.
Why do I get 429 even though I'm under my per-minute limit?
Limits are enforced ~per second. A burst above ceil(RPM/60) requests in one second 429s even when the full-minute total is under the cap.
Are Opus 4.7 and Opus 4.6 rate limits separate?
No. The Opus pool is shared across 4.7/4.6/4.5/4.1/4; Sonnet across 4.6/4.5/4. Splitting traffic across versions does not add capacity.
How do I move to a higher tier?
Auto-advance on cumulative credit purchase: $5 → Tier 1, $40 → Tier 2, $200 → Tier 3, $400 → Tier 4. Immediate on reaching the threshold.
