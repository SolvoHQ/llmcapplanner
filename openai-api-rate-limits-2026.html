OpenAI API Rate Limits Explained (2026): RPM, TPM, RPD & the 429 Error

OpenAI enforces four independent rate-limit dimensions. Any one of them trips a 429. Here is how each works in 2026, the GPT-5 family tier numbers, and the cached-token gotcha that catches teams migrating from Claude.

Four independent dimensions — any one trips 429

OpenAI does not have a single rate limit. It has four, and they are checked independently:

  • RPM — requests per minute
  • TPM — tokens per minute (input + output combined)
  • RPD — requests per day
  • TPD — tokens per day

Exceeding any single dimension returns HTTP 429 Too Many Requests — even if the other three have plenty of headroom. A batch job can pass RPM and TPM all day and still die on RPD at hour 20. You have to size for all four.

Five spend-based, auto-advancing tiers

OpenAI has five usage tiers. You start at Tier 1 (cumulative spend around $5) and auto-advance as cumulative spend grows; Tier 5 requires roughly $1,000 in spend plus about 30 days of account age. Higher tiers raise RPM and TPM by orders of magnitude.

TPM counts everything — including cached tokens

Cached input tokens still count toward OpenAI's TPM. They are billed at a discount, but they are not free against the rate limit. This is the exact opposite of Anthropic, where cache_read_input_tokens do not count toward ITPM. If you are porting an Anthropic capacity model to OpenAI, this is the single biggest correction to make.

Two more TPM rules that surprise people:

  • TPM is input + output combined — not two separate ceilings like Anthropic's ITPM/OTPM. One number absorbs both.
  • max_tokens counts toward TPM. OpenAI reserves your requested max_tokens against the limit at request time. An oversized max_tokens can 429 you even if the model only generates a few tokens. Set it tight.

Per-second quantization

Like Claude, OpenAI's RPM is enforced roughly per second. 1,000 RPM ≈ 17 requests/second (ceil(1000/60)). A burst above that in any one second 429s even though the full-minute total is fine. Smooth your traffic to the per-second figure.

Limits are per-org and per-model

Rate limits apply per organization, not per API key — every key in an org draws from the same pool. They are also per model: GPT-5.5 and GPT-5.4 have separate limits, so routing overflow to a cheaper model is a legitimate (if quality-affecting) capacity strategy.

FAQ

What are OpenAI's four rate-limit dimensions?
RPM, TPM (input+output combined), RPD and TPD. Enforced independently — any one over the line returns 429.
Do cached tokens count toward OpenAI's TPM?
Yes. Cheaper to bill, but still counted against TPM — unlike Anthropic's ITPM, where cache reads are excluded.
Does max_tokens count toward TPM?
Yes. It is reserved against TPM at request time, so an oversized value can 429 you even with short completions.
Are OpenAI rate limits per key or per organization?
Per organization and per model. All keys in an org share the same per-model pool.
How do usage tiers advance?
Five tiers, auto-advancing on cumulative spend (Tier 1 ≈ $5; Tier 5 ≈ $1,000 + ~30 days).
